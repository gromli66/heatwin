## Раздел 2.2: Текущее решение (Current Solution)
*CRISP-DM задача 1.1 — обязательный выход Background*

### Как задача решается сейчас

**Ручное управление (реактивное):**
- Оператор дежурной смены задаёт температуру теплоносителя на выходе из котельной
- Корректировка — каждые 2 часа (Нетбай, 2020) по показаниям термометра температуры воздуха
- Оператор ориентируется на ТЕКУЩУЮ температуру воздуха, без прогноза
- Температура задаётся через интерфейс блока управления котлом

**Автоматическое (по температурному графику):**
- Система автоматически поддерживает температуру по утверждённому «Температурному графику»
- Зависимость T_supply от T_outdoor — линейная или кусочно-линейная (регулировочная кривая)
- В XAI4HEAT: t_ref = уставка из этой кривой

**Плюсы текущего подхода:**
- Простота: не требует ML, IT-инфраструктуры
- Надёжность: оператор визуально контролирует процесс
- Регулировочная кривая проверена десятилетиями эксплуатации

**Минусы текущего подхода:**
- Запаздывание: реакция на ТЕКУЩИЕ условия, не прогноз → при похолодании оператор узнаёт когда уже холодно
- Перетоп: из-за неопределённости организация вынуждена поддерживать заведомо высокую температуру
- Инерционность не учитывается: время запаздывания теплосети (1-6 часов) не компенсируется
- Человеческий фактор: ошибки, усталость, несвоевременная корректировка
- Экономия от устранения перетопа: 5-15% (Нетбай, 2020)

## Раздел 2.5: Терминология (Terminology)
*CRISP-DM задача 1.2 — обязательный выход, два глоссария*

### Глоссарий бизнес-терминов (теплоснабжение)

| Термин | Определение | Пример из HeatWin |
|---|---|---|
| **Теплосеть (DHS)** | Централизованная система: котельная → трубы → подстанции → дома | г. Ниш, 5 подстанций |
| **Теплоноситель** | Вода, циркулирующая по трубам и переносящая тепло | Горячая вода 70-115°C |
| **Первичный контур** | Контур между котельной и подстанцией (высокотемпературный) | t_sup_prim, t_ret_prim |
| **Вторичный контур** | Контур между подстанцией и домами (низкотемпературный), отделён теплообменником | t_sup_sec, t_ret_sec |
| **Подача (supply)** | Направление от котельной к потребителю (горячая) | t_sup_prim |
| **Обратка (return)** | Направление от потребителя к котельной (остывшая) | t_ret_prim, t_ret_sec |
| **Подстанция** | Узел с теплообменником, разделяющий первичный и вторичный контур | L4, L8, L12, L17, L22 |
| **Температурный график** | Таблица/кривая: при T_outdoor = X → T_supply должна быть Y | Регулировочная кривая → t_ref |
| **Уставка (setpoint, t_ref)** | Целевая температура для вторичной подачи, рассчитанная по температурному графику | t_ref в XAI4HEAT |
| **Перетоп** | Подача тепла больше нормативного → потеря энергии | T_return > нормы + Δ |
| **Инерционность** | Время запаздывания между изменением T на котельной и в домах (1-6 ч) | Нетбай: 3 часа для Лысьвы |
| **Калориметр** | Прибор на обратке, измеряющий переданную энергию | delta_e в XAI4HEAT |
| **SCADA** | Supervisory Control And Data Acquisition — система мониторинга и управления | Источник данных XAI4HEAT |
| **Древовидная топология** | Структура сети: корень (котельная) → ветви (коллекторы) → листья (дома) | Рис. 1 в Нетбай (2020) |

### Глоссарий DS/ML-терминов (в контексте HeatWin)

| Термин | Определение | Пример из HeatWin |
|---|---|---|
| **Таргет (target)** | Переменная, которую модель предсказывает | T_return(t + 6h) |
| **Feature** | Входная переменная модели | t_amb, t_sup_prim, lag_24h |
| **Горизонт прогноза** | На сколько часов вперёд предсказываем | 6, 12, 24 часа |
| **MAE** | Mean Absolute Error — средняя абсолютная ошибка в °C | Цель: < 2°C |
| **Conformal PI** | Prediction interval с гарантией покрытия | 90% coverage |
| **Walk-forward CV** | Кросс-валидация для временных рядов (train на прошлом, test на будущем) | Сезон → сезон |
| **SHAP** | SHapley Additive exPlanations — интерпретация вклада каждого feature | Какой feature влияет на T_return |
| **Baseline** | Простая модель для сравнения (naive = «вчера в то же время») | Naive, seasonal naive, ARIMA |
| **Model-free** | Безмодельный подход: зависимости из данных, без физической модели сети | Нетбай (2020), наш подход |

## Раздел 4.1: Формальная математическая постановка (Data Mining Goals)
*CRISP-DM задача 1.3 + Нетбай (2020)*

### Формальная постановка задачи

**Дано:**
- X(t) = {t_amb(t), t_ref(t), t_sup_prim(t), t_ret_prim(t), t_sup_sec(t), t_ret_sec(t), delta_e(t)} — вектор измерений в момент t
- H(t) = {X(t), X(t-1), ..., X(t-L)} — история за L часов (лаги)
- F(t+h) = {t_amb_forecast(t+h)} — прогноз температуры воздуха на h часов вперёд (если доступен)
- h ∈ {6, 12, 24} — горизонт прогноза

**Найти:**
- Модель f: H(t) → ŷ(t+h), где ŷ = T_ret_sec(t+h) — прогноз температуры обратки вторичного контура

**Ограничения:**
- Guardrail (жёсткое): T_ret_sec(t+h) ≥ T_min(T_amb(t+h)) — температура обратки не ниже нормативной
- Нетбай (2020): «полностью исключить отклонение температуры теплоносителя на входе в дома от заданной в меньшую сторону»

**Критерии качества:**
- Technical: MAE(f) < 2°C на test set
- Technical: Conformal PI coverage ≥ 90%
- Business: Σ(T_ret_actual - T_ret_optimal) × c_p × ṁ × τ → min (минимизация перетопа в кВтч)
- Business: Годовая экономия ≥ 5% от baseline (Нетбай: 5-15%)

**Примечание:** в отличие от Нетбая (MLP, model-free), мы используем tree-based модели (LightGBM/XGBoost) как основные, с MLP/LSTM как опциональные для сравнения. Обоснование: деревья не требуют нормализации, имеют встроенный feature importance, быстрее обучаются.
